# Деплой: test и production

## Главное правило

За один запуск изменения отправляются **только в одно окружение**:

- либо на **test**;
- либо на **production**.

Никогда не запускай команды для test и production одновременно, не вставляй их в одну команду и не запускай в двух окнах PowerShell. Сначала проверь изменения на test, затем отдельно и только после явного решения выкатывай их в production.

Если пользователь или постановщик задачи **не указал явно**, куда выкатывать изменения, ничего не отправляй. Сначала задай вопрос: `Выкатываем на test или production?`

## Окружения

| Окружение | Сервер | Домен | Docker Compose-проект |
| --- | --- | --- | --- |
| Test | `87.232.67.145` | `https://test.ct-kubik.online` | `educa_test` |
| Production | `93.125.82.173` | `https://kubik-ct.online` | `educa` |

У test и production разные контейнеры и разные базы данных. Деплой на test не должен выполнять никаких команд на `93.125.82.173`. Деплой на production не должен выполнять никаких команд на `87.232.67.145`.

## Перед каждым деплоем

1. Убедись, что находишься в корне проекта:

   ```powershell
   cd C:\Users\trank\project
   ```

2. Проверь, какие файлы изменены:

   ```powershell
   git status
   ```

3. Убедись, что пользователь явно назвал нужное окружение.
4. Не копируй файлы `.env`, ключи, токены бота и пароли между серверами.

## Выкладка на test

Выполняй только когда пользователь явно сказал «на test» или «на тестовый сервер»:

```powershell
cd C:\Users\trank\project
.\deploy-test.ps1
```

Скрипт отправляет фронтенд и бэкенд только на `87.232.67.145` и запускает контейнеры с проектом `educa_test`.

После завершения проверь:

```powershell
curl.exe -I https://test.ct-kubik.online/
ssh root@87.232.67.145 "cd /opt/educa && docker compose -p educa_test ps"
```

## Выкладка на production

Выполняй только после тестирования на test и когда пользователь явно сказал «на production», «на боевой» или «на рабочий сервер».

Фронтенд:

```powershell
cd C:\Users\trank\project
.\deploy-frontend.ps1
```

Бэкенд:

```powershell
cd C:\Users\trank\project
.\deploy-backend.ps1
```

Production monitor (только после явной задачи на его изменение):

```powershell
cd C:\Users\trank\project
.\deploy-monitor.ps1
```

Если изменены и фронтенд, и бэкенд, запускай скрипты **последовательно**, дожидаясь завершения первого. Не запускай production-скрипты параллельно с `deploy-test.ps1`.

После завершения проверь:

```powershell
curl.exe -I https://kubik-ct.online/
ssh root@93.125.82.173 "cd /opt/educa && docker compose ps"
```

## Запрещено

- Выкатывать без явно указанного окружения.
- Выкатывать в test и production одной командой или параллельно.
- Подменять test-базу данными production без отдельного явного запроса.
- Копировать `.env.production`, токены Telegram-ботов, JWT-секреты или пароли между серверами.
- Использовать `docker compose -p educa_test` на production или обычный `docker compose` для test.
- Выполнять очистку Docker, перезапуск серверов или миграции базы данных одновременно на обоих серверах.

## Если деплой упал

1. Не запускай сразу повторный деплой на другой сервер.
2. Посмотри статус контейнеров только в том окружении, куда выполнялся деплой.
3. Исправь причину, повтори проверку и только затем повтори деплой в это же окружение.
4. Production не трогай, пока test не проверен и пользователь отдельно не подтвердил боевую выкладку.
